# 演示素材来源与录制方式

> 项目名称现已恢复为 `jlc-cli`。本页保留当时的真实录制命令、文件标识及来源，不代表新版本已重新实站验收。

本组视频使用 Codex 的 `gpt-5.6-luna` 执行自然语言指令，配合 `jlc-cli` 和随项目提供的 Skill。视频画面是对本地实时显示的 **Codex CLI 实际事件流**进行录制；不是 Codex 桌面聊天窗口的屏幕录像。指令、命令和输出均来自实际运行，输出经过脱敏和长度裁剪。执行及等待片段为 4 倍速，开头指令和结尾网页截图保留正常阅读时间。

网页截图在业务命令释放连接后，由录制脚本通过 CDP 连接该任务保留的原页面，按 `targetId` 核实对应关系后截取。账号与联系方式在公开素材中遮盖。原始事件、未剪辑视频、原始截图和完整业务结果保存在本机私有录制目录，不随仓库发布。

## 已知边界

- 登录段复用已登录会话，没有重新扫码，不代表完整扫码路径的本次验收。
- 试录期间发现 WebGL 默认不保留绘图缓冲区，造成 CLI 把可见板图判为未就绪。已改用官方画布的可见截图进行像素校验，保留空白画布与文件图标拒绝检查；正式预览段使用修复后的构建。
- 录制期间还发现新窗口参数异步加载导致会话转移误判。比较现改为回读两个页面的当前参数；只有官方预览区显示本次唯一上传文件名时，才允许继续读取已恢复的原文件表单。已有页面身份不一致时仍然拒绝继续。
- 试录中曾因缺少 FR-4 选择和使用旧 draft 进入接管状态；录制者通过 CDP 恢复过该试录的原文件页面。试录素材保留本地，不作为一次无干预成功运行的证据。
- 解析预览视频包含“上传后转移状态不一致”和“CLI 修复后继续同一任务”的两段真实录制，中间修改了本地 CLI；不是一次无干预运行。
- 报价试录遇到“加嘉立创客编”的配置弹窗。录制者取得任务接管租约后，通过 CDP 确认“客编位置无要求、标志增加方式无要求”，释放租约，再由 Luna 通过 CLI 重设、回读参数并报价。报价视频从该接管完成后开始；当前 CLI 对该弹窗的自动操作仍未补齐。

- 下单试录发现官方“订单检查”侧栏遮住旧提交按钮。录制者恢复原文件页面、重设并回读原参数，核对参数哈希与原报价完全一致；修复后 Luna 只恢复原提交任务，没有另建提交任务或重复提交。
- 网站于 2026-09-21 23:14 显示“下单成功”，但成功页不带订单号，原提交任务最终为 `unknown`。随后由 Luna 在独立浏览器配置中只读查询，以完整唯一上传文件名 `jlc-cli-1d8ac93e-fae-CH340N-USB-UART-Gerber` 核实新订单 **Y42**；列表、详情和进度均一致。此结果不代表 CLI 的提交回执自动恢复已经通过。
- 新订单 Y42：5 片，30.00 元，待付款 / 客户确认中，生产和发货尚未开始。`payment prepare` 返回 `PAYMENT_ORDER_NOT_BOUND`，没有生成可确认摘要；没有执行付款确认或扣款。未付款订单仍保留在账号中。
- 第四段由“恢复原提交任务”“独立核实新订单”“查询历史生产工序”三个实际 Luna 会话合成。新订单进度和历史工序各有独立 CDP 截图；历史订单 **Y40** 已发货，显示 MI、钻孔、沉铜完成，不是 CH340N 新订单，也不是数分钟内完成生产。
