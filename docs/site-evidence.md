# jlc.com 适配证据与验证边界

2026-09-21 在 macOS 的 Chrome 中核对当前中国站页面。本适配器调研仅浏览、打开网站提供的计价演示和订单详情；没有提交订单、扣款或发送嘉小智消息。独立 CLI 的业务验收另行记录。以下页面事实支持选择器实现，不等于业务验收完成。原始账号、收货信息、文件记录与带签名资源链接不写入仓库。

## 参数发现的验证范围

匿名独立 Chrome 实测识别 14 个当时可见参数；匿名页许多数据尚未加载，不能作为登录后的完整清单。登录状态下的官网演示确认还存在板材选项、铜厚、阻抗、孔径、金手指、品质赔付、包装、生产基地、出货报告、条码、开票、收货和物流等条件参数。运行时枚举当前页面实际控件，不在代码中固定工艺候选列表。上传文件以任务前缀形成唯一上传名，文件字节不变，并保留原始文件名、SHA-256、大小与时间。打开参数页时记录官方页面的 radomId 导航标识；页面变化使文件关联失效。新窗口复用到任务页面时还要比较参数读回；不一致时保留新窗口并进入接管。`pcb set` 每次变更后重新枚举并报告旧决定被重置和新出现字段。

动态枚举并不证明网站所有条件分支均完成实站验收。无法识别的选择器、未暴露候选值的自定义控件或冲突会返回明确 handoff/needs_input；不假装已设置成功。订单非空 `status` 或非 `1` 的 `page` 尚无完整适配，返回 `ORDER_FILTER_NOT_SUPPORTED`；CLI 默认 `page:1` 可读，精确订单号查询可用。

## 本地浏览器回归

`npx vitest run tests/site.test.ts` 使用独立无凭据浏览器上下文拦截网站 URL，返回明确标识的本地 HTML fixture。测试 native/custom 控件发现、条件字段、依赖重置、default 决策、禁止自动扣款、精确付款绑定、金额改变失效、扣款前回调、指定订单成功信号、无关成功不采纳、不重复扣款、iframe 登录以及二维码缺失。fixture 的合成订单和金额不是实站业务结果。

实际上传解析、对应文件预览、报价后建单、真实余额支付以及嘉小智发送/回复，还需用人类明确授权的真实业务数据执行验收。真实付款必须先呈现并确认本次账号、订单、金额、余额方式；本次开发调研未执行真实付款。

## 接管后的恢复边界

`reconcile` 不点击提交、付款、上传、参数选项或登录按钮。引擎传入 `effectStarted: false` 时，适配器可返回 `resume: true` 交由引擎在原锁与授权门内继续原命令。提交恢复需要原上传页面标识、原账号的新页面核实、全部明确参数与原报价哈希/金额一致；付款恢复需要账号、唯一订单、金额、币种、余额方式与原 binding 一致。参数恢复仅应用原始明确请求，其他已决定字段改变即失效。已经越过副作用边界或边界未知的提交/付款绝不返回 resume。

上传结果关联丢失时，可以使用原 taskId 和原路径读取字节重建唯一上传名以查找现有记录；没有任何重新发送操作。结果关联必须只有一条可见上传记录。登录恢复只核实当前状态和重新捕获实际加载的二维码，不重放密码、验证码或快捷登录。

本地回归覆盖上述恢复条件及失配拒绝、微信快捷登录和绑定决策、空 URL 官方子 frame、隐藏模板重复按钮及非官方 frame 拒绝。测试仍为本地 DOM fixture，不代表真实下单或扣款验收。
