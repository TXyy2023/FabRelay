# 验收步骤与证据边界

本文件区分本地测试、浏览器集成验证和 jlc.com 真实业务验收。只有记录了环境、命令、实际结果与可核查证据的项目才能标为通过。仓库中的测试夹具不是真实订单、报价或付款记录。

本次开发授权允许实现和本地验证，不包含替用户建立真实订单或余额扣款。真实业务验收须使用用户授权的账号、文件与业务操作；付款还须取得针对该笔账号、订单、金额和方式的人类确认。

## 2026-09-21 本地验证记录

环境：Darwin 25.5.0 / arm64、Node.js 25.3.0、Google Chrome 153.0.8010.52、Obscura 0.2.3。Chrome 与 Obscura 版本经运行时 doctor 读取。本节针对本次开发工作区；Windows、Linux 和 Node.js 22.12 最低版本的运行结果须由对应环境另行记录。

| 层次 | 本轮实际结果 | 能证明与不能证明的内容 |
| --- | --- | --- |
| 构建与接口 | `npm run build` 通过；30 个文档命令的 `--help` 及所用选项核验通过，另核对新增 `--clear-endpoint` | 命令语法与文档一致，不代表网站业务完成 |
| 核心单元测试 | `npx vitest run tests/engine.test.ts` 本地回归通过；覆盖确认绑定、凭据剔除、持久化、并发、重放限制及回调 | 使用 mock，不是真实付款或订单 |
| 独立风险复验 | 同一订单两份确认只能触发一次付款；同上传的两份草稿只能提交一次；过期锁 100 轮、每轮 6 个并发调用无重叠，操作锁与恢复持有者均退出时仍可恢复；跨任务接管租约互斥；带凭据端点拒绝；端点清除生效；最终结果保存后中断仍可补投回调一次 | 使用临时目录、mock 及本机回调接收端，无真实业务副作用 |

| Chrome 运行时 | 跨进程同页面保留、单客户端限制、存储恢复、诊断脱敏、缺失页面失败及外部浏览器安全断连已验证 | 详见 [浏览器记录](browser.md)，不能替代 Obscura 的业务验收 |

网站 DOM 调研范围、当前文件限制和参数覆盖边界见 [站点证据](site-evidence.md)。尚未实际执行用户文件上传解析、对应预览、完整参数报价、建单、余额支付及嘉小智消息发送/回复；这些项目继续保留为未验收。

## 记录格式

每次验收保存日期、系统/CPU/Node/浏览器版本、所用提交、匿名账号配置名、命令、预期、实际、证据路径和结论。真实订单号和截图等本地证据可保留在用户控制的位置，公开报告仅使用必要且经脱敏的信息。不得记录 Cookie、密码、短信验证码、回调密钥或浏览器会话文件。

失败或未执行项应写出实际原因与剩余条件。未完成的真实账号与付款验证不由模拟结果补齐；上线结论必须保留这些限制。
